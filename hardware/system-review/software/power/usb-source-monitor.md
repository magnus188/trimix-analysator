# USB CC source observation contract

Implemented `usb_source::Monitor` over the managed `system_i2c::Bus`. This is source observation and controlled interrupt handling only. It does not configure BQ25895 charging, interpret BC1.2, drive GPIO50, arm the ILIM latch, or grant permission to draw current.

The verified TUSB320LAI RWB pin contract is1CC1,2CC2,3PORT,4VBUS_DET,5ADDR,6INT_N,7SDA,8SCL,9ID,10GND,11EN_N,12VDD. Tie PORT/ADDR/EN_N low for enabled sink operation at0x47. Internal Rd remains present without VDD; old external Rd must not be paralleled. VBUS_DET requires its series resistor (RevD855–920kohm), not direct VBUS. Non-failsafe pins and I2C must respect device-supply sequencing. REG08[5:4] decodes00default,01=1.5A,10audio-accessory charging,11=3A. Only REG09[7:6]=10 is attached.SNK. REG09bit4 is W1C and must be verified cleared. [TI TUSB320LAI datasheet, sections5–7.5](https://www.ti.com/lit/ds/symlink/tusb320lai.pdf)

`poll()` never writes. Each poll checks the full ASCII device ID, qualified revision0x02, termination/mode configuration and two coherent status snapshots. Unknown identity/revision, source/DRP configuration, accessory states, partial reads and changing snapshots produce no capability. Detached remains valid information with no current class. USB default carries `advertised_ma=0`: USB enumeration and BC1.2 interpretation belong to the power policy. A stable sticky interrupt increments observation generation only once; changed state, new interrupt assertion or communication failure/recovery invalidates earlier observations.

Both mutation APIs require the caller to hold the independent ILIM permission command LOW throughout. `initialize_disabled_policy()` sets only the accessory-disable control bit and preserves pending IRQ. `acknowledge_change(expected, after)` obtains a fresh coherent observation, compares generation/source/configuration, writes only the writable control bits plus W1C, then verifies that the interrupt cleared and the same observation remains. It returns false for a new event, source change, ignored/failed write, failed readback or stale expected observation. The output may contain useful diagnostics even after failure; failure must never be treated as permission. Passing the same object for expected/output is supported without losing the expected identity.

The external latch/detach reset and series-FET arrangement is a separate hardware/policy contract still under review. Neither a driver read nor an IRQ acknowledgement proves that hardware permission is low, that a source cannot change immediately afterward, or that a GPIO stalled high is safe. Runtime integration must retain independent hardware reset and requalification behavior.

Validation:51 host assertions passed in a strict warning build, and the same51 passed AddressSanitizer/UndefinedBehaviorSanitizer without diagnostics. Tests exercise all current/accessory codes, detached/source roles, startup configuration, coherent read races,100 read-only sticky-IRQ polls, failed/ignored configuration, W1C readback, same-class new events, source downgrade during acknowledgement, aliasing, unknown IDs/revisions and partial transport failure/recovery. No device, cable, charger, dead-battery or power-latch test was performed.
